# Typed PipeView style foundation

The explicitly selected native model-view compiler supports
`pipelang.native-view-styles.v1`: reusable named styles scoped to one source file
and selected explicitly by one view. This is an initial typed style capability,
not CSS/SCSS compatibility or full PV-03 acceptance. It adds no Go implementation.
Legacy view profiles retain their existing grammar and defaults.

```text
style Theme {
    token inset: length = 16px;
    token ink: color = "#EAF1F8FF";
    padding: inset;
    gap: 10px;
    text: ink;
}
style Compact extends Theme {
    override token inset: length = 10.5px;
    override gap: 4px;
}
view SettingsView(model: SettingsModel) style Compact {
    Column(id: "root") {
        Label(id: "title", text: "Settings");
    }
}
```

Declarations precede the view. Style and token references may point forward.
Tokens have exactly `length` or `color` type; values are literals or token names.
Lengths use nonnegative finite decimal literals with logical `px` units; colors
use quoted exact `#RRGGBBAA` values. Units may be separated by whitespace.
No arithmetic, model binding, implicit unit conversion or string-to-color
coercion occurs. Standalone tokens are finite; property bounds apply on use.

Inheritance resolves base members, then local members. Replacing an inherited
token or property requires `override`; an override without an inherited member
refuses, as does changing a token's type. Inherited property and token expressions
resolve against the effective child token scope, so overriding a token updates
all inherited properties referencing it. Token and property names occupy their
own scopes. Duplicate declarations, cycles and unknown references refuse.
Every declaration and effective token is checked, including unselected styles.
There is no implicit global cascade, source-order specificity or automatic style
selection. An unselected style has no effect on the generated view.

The initial adapter profile maps these properties to the existing public
ForgePipe 0.9.0 `Document::style` contract:

| Length property | Inclusive logical-pixel range |
| --- | --- |
| `padding`, `gap`, `textInset` | 0–64 |
| `labelHeight` | 1–128 |
| `controlHeight` | 1–256 |
| `fontPixelHeight` | 7–56 |
| `borderWidth` | 0–8 |

Color properties are `background`, `control`, `field`, `border`, `focus`, `text`
and `disabledText`. Unspecified properties retain backend defaults. The host owns
`scale`; authoring it refuses. Existing focus and disabled behavior use their
palette entries; this does not introduce arbitrary interaction-state selectors.
The compiler validates the shared profile without linking a renderer. Generated
bridges assign resolved constants to the existing style object. Models, event
admission, action dispatch, async ownership and inspection identities are unchanged.
The native view manifest and style-free generated bytes remain unchanged.

Admission bounds are 32 styles, 32 own/effective tokens per style, the 14 listed
properties, inheritance and token-reference depth 16, and 4,096 total resolution
work units. Repeated resolution counts toward the work bound. Existing source,
lexer, transport, view-node and output limits also apply. `PMV2001` diagnostics
identify the authored property/reference span. Lexer failures keep their existing
category. Invalid candidates produce no generated success artifact.

Selectors, component parts, nested rules, arbitrary interaction selectors,
percentage/em units, imports, XML styles, Qt mappings and reload remain planned;
unsupported authoring refuses. The settings showcase proves authored style
changes separately from model/action behavior. Headless draw/layout evidence
is not visible UI, physical input, GPU, cross-platform or release qualification.
