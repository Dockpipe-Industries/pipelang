# Native binary64 helper calls

Additive selection: `pipelang.cpp.float64-calls.v1`, native request/response v4.
No implicit profile selection or Go fallback. Go reference C++ emission refuses
this new profile; the explicit SHA256-pinned native executable is required.
Existing pilot/v2/v3 requests, responses and generated bytes remain unchanged.

The profile composes the existing conditional expression subset with arbitrary
pure typed intra-program calls. Targets follow existing Core semantics: same
package and semantic owner, exact full source callable identity/name, matching
argument and return representations. Both bool and binary64 functions, arguments
and results are admitted, including zero parameters, forward references, nested
calls, Boolean conditions and calls in conditionally evaluated arms. No new Core
schema, language semantics, Go evaluator or Go emitter capability is introduced.

Calls are wire objects containing exactly `kind`, `type`, `callee`, `arguments`.
`callee` has exactly `package_id` and `path`; `arguments` is always an array,
including an empty array for zero parameters. Native validation independently
resolves the target, checks same-owner/package, arity and exact argument/result
tags, refuses unknown targets and all direct/indirect recursion, and checks the
whole graph before emitting output. Generated forward prototypes make function
ordering irrelevant to declaration availability.

Arguments evaluate once each, left to right, into typed named temporaries before
invocation. Conditional and logical short-circuit operands retain lazy evaluation.
Only selected conditional branches run. Functions are pure; no I/O or mutable
state enters this profile. Finite literal reconstruction and the established IEEE
binary64 host domain (including infinities, quiet NaNs, subnormals and signed
zeros) remain unchanged. Signaling NaNs and nondefault floating modes remain
outside qualification.

Existing bounds remain: 128 functions, 64 parameters, 4096 aggregate expression
nodes, expression depth 64, 16 MiB request, 32 MiB response and process limits.
Additionally each entry is conservatively bounded to 4096 transitively expanded
expression evaluations and call depth 64. Cost sums all child expressions and
adds each invoked target's cost, including both conditional arms conservatively.
Memoized DAG summaries bound validation itself and prevent exponential runtime
work despite a small acyclic source graph.

ForgePipe ContactCoefficientsValid now composes WithinClosedRange and
ContactOrderValid in its previous order. The exact five public private-binding
identities remain unchanged. Default C++, field errors, finite guards, optional
capabilities, arithmetic and transactional outputs remain ForgePipe owned.
Configure/workflow/package/binding admission rejects a missing native emitter.

Prepared tests: closed Core identities/signatures/payloads, old-profile refusal,
native-only emission, v4 exact wire refusals, cycles and transitive resource
bounds; source-through-native IEEE bit/classification oracle plus existing Core
behavior; zero/forward/nested/Boolean calls and ordered-once/lazy literal traces;
Forge binding and SDK-package admission tests; retained installed public material,
contact and combine fixtures compare default against native calls. Execution is
parent coordinated under the aggregate containment budget. No tests/builds were
run by the implementation agent.
