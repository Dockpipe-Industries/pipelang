# Experimental C++ binary64 comparison profile

## Contract before implementation

The additive capability identity is `pipelang.cpp.float64-comparison.v1`.
Existing `pipelang.cpp.pilot.v1` behavior, generated bytes, runtime header and
private v1 emitter protocol remain unchanged. Go source admission, semantic
analysis and HIR/Core lowering remain authoritative and default. This is a
backend capability subset of language `v0.113.0` and `pipelang.compiler.v1`;
it introduces no new source spelling, Core operation or arithmetic semantics.

### Selection and admission

Add `cppbackend.Float64ComparisonCapability`,
`ValidateProfile(program, profile)`, `GenerateWithProfile(program, profile)` and
`NativeEmitter.GenerateWithProfile(context, program, profile)`. Empty/unknown
profile names fail; existing APIs continue selecting the existing pilot.

`pipelang-native-cpp --profile pipelang.cpp.float64-comparison.v1` selects the
new capability. Omitting `--profile` retains `pipelang.cpp.pilot.v1`. Existing
paired `--cpp-emitter`/`--cpp-emitter-sha256` and optional lexer selectors retain
exact executable admission and no fallback. The Go emitter remains default for
either profile. Unsupported source/Core/profile/process outcomes fail before
writing either output artifact.

Functions return bool and accept only source `float` or `bool` parameters.
`float` normalizes to Core numeric/binary_float/64/signed=false and C++ `double`;
bool remains primitive/bool and C++ `bool`. The complete selected expression
set is parameter references, finite binary64 and Boolean literals, logical not,
short-circuit and/or, six same-type binary64 comparisons, and bool equality or
inequality. No function calls, local/block expressions, conditional expressions,
float return values, arithmetic, numeric negation, casts, records, carriers or
collections are admitted. Source float literals retain the existing decimal
spelling rules; direct Core negative literals are allowed when finite.

Limits: 1..128 functions, at most 64 parameters per function, 4096 expression
nodes over the program and expression depth at most 64. Core pointer cycles,
contradictory representations, inactive expression payloads, noncanonical
positions, type mismatches and malformed identities fail before projection.
Full owning Core validation still runs before emission. The CLI retains its
64 KiB source and 16 MiB generated-source bounds.

### IEEE behavior and generated ABI

Runtime binary64 parameters preserve the existing comparison domain: finite
values, subnormals, positive/negative zero, infinities and NaNs. There is no
finite-only argument validator or new runtime exception. NaN is unordered,
`!=` is true for NaN, and signed zeros compare equal. Boolean evaluation retains
left-to-right short circuiting. This does not promise signaling-NaN exception
flags or NaN payload transport because every exposed result is bool.

Generated C++17 headers require IEEE-754 binary64 `double` (size, radix,
precision, exponent range and IEC559 checks) and reject `__FAST_MATH__`,
positive `__FINITE_MATH_ONLY__`, and MSVC fast floating-point mode. Qualification
also checks actual subnormal behavior; changing runtime floating-point modes is
outside this slice. The profile has a separate support header and does not edit
or emit the pilot runtime. Literal reconstruction copies exact uint64 bits into
`double` with `memcpy`; no reinterpret-cast aliasing, decimal reparsing, integer
conversion or arithmetic is used.

Output filenames and export contract remain `generated.hpp`, `bindings.json`,
`pipelang.native-cpp-export.v1`. Metadata `profile` identifies this capability;
existing source/generated/frontend and selected native companion hashes remain.
Binding metadata retains authoritative semantic identity and Core parameter
representations. Symbols keep `pipelang::fn_` plus the existing 24-hex digest of
package-id, NUL and semantic path. Generated signatures are inline bool functions
with double/bool parameters in declared order, so consumer adapters can retain
ordinary synchronous bool behavior without ABI/export changes.

The intended ForgePipe source methods are:

```text
public Class MaterialAdmission {
    public bool WithinClosedRange(float value, float minimum, float maximum)
        => value >= minimum && value <= maximum;
    public bool ContactOrderValid(float dynamicFriction, float staticFriction)
        => dynamicFriction <= staticFriction;
}
```

The consumer owns finite bound constants, JSON admission, field/error ordering,
optional capabilities and transactional outputs. Closed comparisons with its
finite bounds reject NaN/infinities naturally. No engine source belongs in this
compiler repository; no sibling source dependency is introduced.

### Private selected wire protocol

Use additive `pipelang.cpp-emitter.request.v2` and
`pipelang.cpp-emitter.response.v2` exclusively for the new profile. The v1
protocol remains selected for the existing pilot. Every new message requires
its exact profile and contract, has a 16 MiB request / 32 MiB response bound, and
uses exact case-sensitive member sets, duplicate/missing/unknown-member refusals,
strict scalar types, bounded nesting/nodes and Unicode scalar preservation.

Request members are `contract`, `profile`, `language_contract`,
`compiler_contract`, `functions`. Each function contains `package_id`, `path`,
`parameters` (array of `float64`/`bool` tags), and `body`. Callable identity stays
Go-authoritative; the native component receives only the validated normalized
subset needed for this emission responsibility.

Expression objects always carry `kind` and `type`. Reference additionally has
integer `parameter`; bool literal has `boolean`; float literal has
`float64_bits`, exactly 16 lowercase hexadecimal digits for finite IEEE bits.
Unary/binary expressions have `operator` and an `operands` array of exactly
one/two expressions. There are no nullable/inactive members. The native process
independently verifies each expression's closed shape, types, operator,
parameter reference, finite literal bits and resource bounds before emission.

Response members are `contract`, `profile`, `source`, `functions`. Each binding
contains `package_id`, `path`, `name`. Go verifies the exact sorted binding count,
identities and deterministic symbols and reattaches its admitted full semantic
identity. Header bytes from the reference Go emitter and selected C++ emitter
must match exactly. The process uses the shared checksum-before/after,
cancellation, 30-second deadline and bounded-output adapter, without fallback.

### Required focused proof

Cross all six comparisons over the existing independently-oracled binary64
matrix (infinities, extrema, signed zeros, subnormals, adjacent values, multiple
NaNs), plus Boolean short-circuit combinations and finite range/contact guards.
Compare Core evaluator, generated Go, Go-emitted C++ and native-emitted C++.
Compare exact finite literal bits and generated headers, including negative
zero in direct Core, extreme finite literals and subnormal literals. Preserve
existing pilot generation/receipts byte-for-byte apart from executable identity.

Reject unsupported types/operations, malformed/inactive Core payloads, unknown
profiles, non-finite literal bits, malformed new wire messages and selected
process/checksum failures. Verify unsafe compiler flags fail header compilation.
Generated execution and native build checks use existing job.py/run.py limits;
no uncontained fallback, limit increase or full-suite/performance claim follows.

## Verification

Local focused qualification passed on 2026-10-30. Retained source preimages,
tool hashes, generated artifacts and job/worker receipts are under
`/tmp/pipelang-forgepipe-overnight-20261030/float64-profile/`; `acceptance.json`
indexes the final sources and tools. `rebuild-3`/`rebuild-job-3` built the final
native emitter, and `focused-5`/`focused-job-5` passed both focused Go packages
with all native/generated execution explicitly enabled.

- 2,248 independent cases matched the Core evaluator, generated Go, Go-emitted
  C++ and native-emitted C++: all six comparisons over 14 × 14 IEEE values,
  contact ordering, Boolean composition, finite ranges and Boolean equality.
- 100 finite-literal comparisons agreed across the same execution paths. Ten
  exact binary64 reconstructions covered signed zeros, signed subnormals,
  signed minimum-normal/extreme-finite values, 0.1 and -1. Go/native header bytes
  matched, including every literal's exact hexadecimal payload.
- An instrumented generated-header trace verified both short-circuit outcomes.
  GCC rejected `-ffast-math` and `-ffinite-math-only`. The generated header also
  contains the MSVC `_M_FP_FAST` refusal; MSVC itself was not qualified here.
- Closed Core and native-wire checks rejected malformed types, members,
  identities, references, inactive payloads, nonfinite literals and resource
  excess. Selected process/hash/cancellation/deadline and malformed-response
  failures returned no generated result. Additional `utf8-1`/`utf8-job-1`
  process-level regressions confirmed the existing shared transport refuses
  malformed raw UTF-8 in source/binding strings before JSON decoding, while
  preserving valid Unicode source and binding identities. Seven CLI refusal families preserved
  both absent output directories and existing artifact sentinels.
- Four existing pilot fixtures produced identical headers and metadata across
  the immutable accepted baseline, current default Go, explicit pilot Go and
  current native pilot; only compiler/emitter executable hash fields differed.
  Existing Go pilot generation, native pilot emission and runtime header bytes
  remain unchanged. Native dispatch reuses the original bounded JSON parser
  once per request for either contract.

Accepted job/worker receipts report exit zero, removed process trees, zero swap
and no OOM events under unchanged limits. Earlier failed attempts remain in the
proof directory: an invalid two-record comparison test fixture was corrected;
a sandbox bus refusal and one missing harness cache argument ran no workload.

These checks qualify the local Linux/GCC default floating-point environment,
including gradual subnormals. They assume DAZ/FTZ remain disabled and make no
rounding-mode, floating exception flag or signaling-NaN claim. This is focused
backend/CLI proof, not a full compiler campaign, performance claim, installed
consumer acceptance or cross-platform release qualification. ForgePipe's
consumer retains its owning `std::isfinite` precheck and JSON/error ordering.
