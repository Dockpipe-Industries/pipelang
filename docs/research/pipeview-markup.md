# PipeView XML frontend and settings round trip

The first PV-06 slice adds optional XML authoring over the existing v1 event and
v2 managed-action profiles. The primary PipeLang syntax remains unchanged. XML
lowers through compiler-owned canonical view formatting and the existing source
checker to the same neutral document and typed state/action plan. Core state,
inspection, testing and ForgePipe transport packages acquire no XML dependency.

The public API is `sdk/pipeview/markup.ToSource`, `FromSource` and
`CompileProgram`. The compiler owns `FormatViewSource`; the optional view CLI
owns explicit syntax/output selection and separate source-conversion receipts.
The format and limits are recorded in the
[contract](../concepts/pipeview-markup.md). XML syntax failures identify authored
byte offsets; shared type checking identifies generated PipeLang. Semantic source
maps remain outstanding. This slice does not implement Qt `.ui` import, QML,
styles, conditional/list components or reload.

Local proof is retained at `/tmp/pipeview-markup/acceptance.json` with bounded job
and worker receipts. The build and baseline test workflows used installed
`/usr/bin/dockpipe` 0.6.33. A temporary validation copy omitted the repository's
older exact CLI gate, as recorded in `validation-exception.json`; committed
configuration and lock files were preserved. No DockPipe source was accessed.

Focused coverage includes canonical formatting and AST refusal; typed source and
XML round trips; bool/empty-string/int64 extremes; literal braces, Unicode and
XML escapes; CR/LF/tab preservation; profile and binding/action compatibility;
unknown/duplicate attributes; namespaces, directives, declarations and mixed
content refusal; byte/node/depth/declaration limits; explicit foreign lexer
failure; output safety; receipt identities; and optional dependency boundaries.
An adversarial surrogate numeric reference exposed silent replacement in the
standard XML decoder. Original token bytes are now checked before admitting
numeric references, while valid replacement characters and comment text retain
their meaning.

The complete XML settings example is selected with
`PIPEVIEW_VIEW_SYNTAX=xml`. Original PipeLang, XML and round-tripped PipeLang
generated byte-identical document/model headers with Go and native lexer
selection, matching the previously accepted settings artifacts. Both native
settings consumers use the qualified installed ForgePipe 0.9.0 SDK; its archive
checksum and 159 expanded regular files were rechecked. No engine sources were
copied or built. Existing settings/store/worker fixtures passed for both builds.

Six native inspection states from each XML-authored build matched the Go typed
test host: initial, redacted, edited, saving, saved and reverted. The final tool
was rechecked against the actual compiled header bytes. Native visible proof
then exercised Save and second-process reopen with the native compiler
components and installed SDK. PNG and redacted inspection artifacts accompany
the receipts. These are bounded synthetic-input Linux X11/Vulkan checks; they
do not qualify physical input, accessibility, other platforms or release builds.

Source edits stay in PipeLang, including the settings example. ForgePipe and
MesaMoto source, inherited attribution, C++ runtime behavior and frozen compiler
goldens remain unchanged. The local optional authoring binary is refreshed for
continued development; no commit, push, publication or system-wide installation
is part of this slice.


A subsequent [diagnostic-mapping slice](pipeview-markup-diagnostics.md) adds
authored element locations to typed XML failures. The original checkpoint above
retains its historical diagnostic limitation and receipts.
