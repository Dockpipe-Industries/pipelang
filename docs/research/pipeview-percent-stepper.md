# PipeView fixed percent stepper

## Contract before implementation

This bounded PV-02 slice adds `PercentStepper`, a fixed integer 0..100 editor,
and a persisted volume setting to the canonical PipeLang settings showcase.
It adds no source grammar, language/Core operation, scalar backend profile,
general action body, floating arithmetic, audio-engine gain application or
renderer startup. Existing event/source v1 and action/source v2 examples retain
their generated bytes when they do not use the new component.

### Portable component and capability

The Go constructor is `PercentStepper(identity, label string,
binding Binding[int64], changed Event[int64]) Node`. Source spelling is
`PercentStepper(id: "volume-stepper", label: "Volume", value: bind volume,
changed: volumeEdited)`. Its only properties are id, optional label, value and
changed. Value must bind int state; changed must have an int payload and, in an
action view, target that exact binding. No min/max/step properties exist.
The current scalar model, signed-64-bit payloads and set/save/revert plan remain
unchanged. Existing node/depth/text/identity bounds still apply.

A document containing the component advertises
`pipelang.pipeview.declaration.v2`; unchanged documents retain declaration.v1.
Forge transport uses `forgepipe.ui.v2` only for those documents; the exact node
kind is `percent-stepper` and its named action is required, never empty. Old schema v1
must reject percent-stepper nodes; a v2 document uses the existing node fields
and integer state transport. No fields are added to ForgePipe's public C++ Node.
The new ControlType value and input enum values are appended, preserving old
numeric values and struct layouts. Old installed SDKs must refuse v2 decoding,
not silently render a fallback. View export metadata carries the selected
adapter schema; generator/admission must compare that actual schema exactly.
Source v1/v2 identities retain their grammar/action meaning. Inspection uses
`pipelang.pipeview.inspect.v2` only for new-component documents; old frames
retain inspect.v1. Typed test handles submit canonical integer payloads through
the existing declared action, including invalid integers used for validation tests.

XML represents the same component/properties and typed bindings. Go and native
view parsers use their unchanged generic component/property syntax. Unsupported
conversion refuses rather than dropping the control. Native parser selection
for XML remains refused exactly as before.

### Gesture and state semantics

PercentStepper has one focus identity. Left/Decrease requests a decrement;
Right/Increase requests an increment. Pointer down in the left half decrements,
in the right half increments. Keyboard Left/Right and controller Decrease/Increase
are appended explicit input values. Tab/Next/Previous retain focus traversal.
Shift does not reverse Left/Right; existing Shift+Tab traversal is unchanged.
Enter/Space/Activate on the stepper performs no value change, avoiding an implicit
increase through generic activation. Pointer activation still focuses the control.

For a current integer inside 0..100, a gesture changes it by one unless already
at that direction's boundary. A current value below zero recovers to zero on
either direction; a value above 100 recovers to 100 on either direction. Recovery
happens before arithmetic, including INT64_MIN/MAX, with no overflow. Unchanged
boundary gestures succeed even when the queue is full, produce no event and do
not consume queue capacity. A changed
gesture checks event capacity before changing presentation state, then emits
one ValueChanged event with declared control/action/binding and int64 value.

The raw int64 model draft remains authoritative. Canonical but out-of-range set
payloads retain existing semantics: they enter the draft, domain validation marks
it invalid, visible value remains the exact integer, and Save refuses. Projection,
Document admission and Session::setValue must not clamp or reject raw int64 values
merely because they are outside the gesture range. Rejected/busy host events
re-project the model. The stepper renders the exact raw decimal integer followed by '%' with visible
'-' and '+' decrease/increase affordances; headless draw-list tests qualify
content, not visual polish. The stepper does not format a clamped value; model status reports
Invalid settings. UI state is a disposable projection, never a second saved model.

### Canonical settings and storage

Only PipeLang examples/settings gains application behavior. ForgePipe's existing
counter/settings integration fixtures remain unchanged. The new initial volume
is int64 100. `Settings.pipe` adds the existing-pilot pure predicate
`IsValidVolume(int value) => value >= 0 && value <= 100`; host validation combines
it with IsValidName. The generated model definition includes volume and its set
action. The same owned worker captures an immutable complete settings snapshot;
completion rules and stale-ID refusal remain unchanged.

`pipeview.settings.v2` extends the exact existing length-prefixed player-name,
VSync format with one final decimal volume line after the VSync line. Volume
and the v2 name-length field must have canonical unsigned decimal spelling (0 or a nonzero digit followed by
digits), no sign/leading zeros/space, and volume value 0..100. Legacy v1 length admission remains unchanged. v2 malformed/trailing,
overlong or out-of-range values fail with the existing optional-load outcome: empty result and no partial
candidate. Unaffected v1 errors retain their existing behavior. Existing regular
file, no-follow, bounded-read and atomic-save behavior remains.

A valid v1 file loads in memory with volume 100. Loading never rewrites it.
Only an explicit successful Save writes v2. An absent file uses initial defaults;
invalid files fail rather than resetting. The loaded v1/v2 snapshot is the saved
baseline for Revert. No fixture uses real user paths. Parent-directory durability,
concurrent writers and renderer/audio application are outside this slice.
