# PipeView typed state/actions and settings Save

Status: locally implemented and verified, 2026-10-28. This advances the bounded
PV-02 settings slice, not the complete UI/language/state/task roadmap. Go remains
the reference. No existing language/Core/Application IR contract is promoted.

The subsequent [owned-worker increment](pipeview-owned-save-worker.md) moves
host persistence off the UI thread; the proof below remains the historical
synchronous-host checkpoint and was preserved rather than rerun as a compiler
experiment.

## Ownership and changes

The canonical new settings showcase is `examples/settings` in PipeLang. The
previous ForgePipe settings/counter folders are integration fixtures; this slice
did not edit them or any ForgePipe engine source. The showcase consumes the
qualified installed ForgePipe SDK through exact CMake targets.

- The compiler's explicit view parser accepts typed `action` declarations and
  one qualified binding member. The optional source package admits the closed
  set/save/revert profile, checks control/target/payload agreement, and projects
  read-only Save status. Legacy event views remain source v1; managed actions
  require source v2. Legacy `Compile` refuses to drop action plans.
- `sdk/pipeview/state` owns the Go reference draft/saved model and typed operation/
  terminal-outcome contract. It has no compiler, renderer, I/O or scheduler
  dependency. Its bounded C++ companion is embedded from one SDK-owned header
  into generated v2 artifacts, with an exact runtime hash in completion metadata.
- The CLI emits the checked model definition and status bindings alongside the
  existing document. The original v1 artifact format stays unchanged; new
  optional metadata appears only for the action profile.
- `SettingsView.pipe` owns typed fields and actions. `Settings.pipe` supplies the
  pure compiled nonempty-name validator through the existing Go semantic/HIR/
  Core/C++ pipeline. The host admits its complete semantic identity and signature.
- The application owns an explicit-path file store and presentation adapter. Save
  persists the captured typed snapshot; a matching successful completion advances
  the baseline. Failure preserves draft/baseline for retry. Revert uses the saved
  baseline, including loaded settings. Session input is staging, never the source
  of application truth when saving.

See the [state/action contract](../concepts/pipeview-state-actions.md) and
[showcase instructions](../../examples/settings/README.md).

## Limits and continuation

These are UI-library state semantics and closed handlers, not arbitrary language
mutation, effectful action bodies or tasks. Hosts own persistence and request
lifetime. IDs are model-scoped; cancellation cannot undo a committed external
operation. The showcase processes I/O synchronously on the next owner-thread tick;
background work and a UI Cancel control remain pending.

CanSave is enforced, but visual dynamic disabling awaits backend capability.
The persisted VSync value does not alter the renderer mode. Persistence has
bounded typed data and atomic file replacement, not directory crash durability
or multiprocess merge guarantees. Corrupt saved data refuses instead of silently
resetting. Native glyph input remains ASCII. Styles, XML, hot reload, richer
settings/validation, live AI inspection and Qt/QML proof remain in the roadmap.

No commit, push, publication, system installation, DockPipe source edit or ForgePipe
source edit is included. Existing license/provenance and inherited work remain intact.
