# PipeView settings showcase

PipeLang owns this application example: authored view/actions, state model,
compiled validation, persistence and native host wiring. ForgePipe is a versioned
installed rendering/input dependency. Its repository is not needed to build this
showcase, and the application runs without DockPipe or Go installed at runtime.
DockPipe remains the development workflow runner.

`SettingsView.pipe` declares typed fields and `set`/`save`/`revert` actions. The
optional source frontend checks the declaration and generates the neutral UI
transport plus the bounded native state runtime/definition. `Settings.pipe`
provides the compiled nonempty-name and integer volume validators. No view JSON, stringly typed
method lookup, runtime source interpretation or duplicated state controller lives
in the application.

Build with a qualified ForgePipe SDK 0.9.0 that explicitly supports
`forgepipe.ui.v2` / PercentStepper and exact compiler tool hashes. Older SDKs
refuse the new control; no fallback to a string field is provided:

```sh
cmake -S /absolute/path/to/pipelang/examples/settings -B /tmp/pipeview-settings \
  -DCMAKE_PREFIX_PATH=/absolute/path/to/ForgePipe-SDK-0.9.0-Linux \
  -DPIPELANG_CPP_COMPILER=/absolute/path/to/pipelang-native-cpp \
  -DPIPELANG_CPP_COMPILER_SHA256=EXACT_LOWERCASE_SHA256 \
  -DPIPELANG_VIEW_COMPILER=/absolute/path/to/pipelang-viewc \
  -DPIPELANG_VIEW_COMPILER_SHA256=EXACT_LOWERCASE_SHA256
cmake --build /tmp/pipeview-settings --parallel 2
ctest --test-dir /tmp/pipeview-settings --output-on-failure
/tmp/pipeview-settings/pipeview-settings-native \
  --settings-file /absolute/path/to/owned-fixture/settings.data
```

The settings parent directory must exist. No user profile or default settings
location is discovered. The fixture contains player name, Boolean VSync and integer volume (0..100,
initially 100). The PercentStepper displays the raw percentage with minus/plus
affordances; Left/Right changes by one. Invalid canonical drafts remain visible
and cannot be saved. Volume is persisted data, not an audio-engine gain change. Save captures a typed draft; failure preserves it for retry; Revert restores
the saved baseline. Reopening the app loads successful saves. Source and storage
schemas must match. Valid v1 files load volume 100 in memory without rewriting.
Only explicit successful Save writes the v2 codec, including canonical decimal
volume. Invalid or out-of-range v2 files fail startup.

Optional `PIPELANG_CPP_LEXER`/`PIPELANG_CPP_EMITTER` and corresponding SHA256 CMake
inputs select the existing native compiler components; Go remains the reference.
The authoring-tool build flag `PIPELANG_BUILD_PIPEVIEW_EXAMPLE=1` produces both
required tools through the existing PipeLang build workflow. Build-time admission
checks source, generated bytes, full callable identity/signature, source/runtime
contracts and tool/component hashes. Native runtime identity is part of the view
receipt. The application imports no engine implementation sources.

For bounded native verification, `--proof-dir ABS` captures eight visible frames;
`--proof-mode save`, `reopen` or `failure` selects an explicit synthetic-input
fixture. Save expects a fresh settings file, reopen expects the prior `RiderX`/
VSync-false/volume-99 save, and failure expects an unavailable parent directory. These are
proof options, not physical-input qualification. The model fixture additionally
checks invalid/clean Save, pending edit refusal, retry, reload, baseline Revert,
presentation bypass, corrupt data and symlink/nonregular refusal.

Earlier player-name/VSync evidence qualified the Linux X11/Vulkan native profile.
The PercentStepper extension has separate headless qualification; it does not
inherit physical-input or rendered-presentation acceptance from that evidence. Native text remains printable
ASCII. File replacement is atomic with file flushing, without a parent-directory
crash-durability guarantee. Save runs in one owned background worker; the owner thread polls completion
without waiting and applies the matching model result. Startup loading remains
synchronous. Closing joins an already-started save before model/view teardown;
it does not cancel or roll back a write. General PipeLang tasks remain future work. CanSave policy is enforced while dynamic visual
button disabling awaits backend support. This is an experimental closed action
profile, not arbitrary action bodies or full language state/task semantics.

## Inspection and automation fixtures

Explicit native proof runs now emit redacted semantic files beside their PNGs:
`inspection.json` and, during Save, `pending-inspection.json`. State values require
an explicit allowlist; normal startup writes no inspection files and exposes no
endpoint. Static labels/model status remain visible, and PNGs themselves are not
redacted. Capture runs on the model owner thread and reports authoritative state.

The BUILD_TESTING-only `pipeview-settings-inspection ROOT OUTPUT` fixture produces
six known-value frames through real Session input. The Go typed widget harness
must match them exactly. Go test hosts use the same declared action IDs and real
reference model, not raw state mutation or sleeps. See the
[inspection contract](../../docs/concepts/pipeview-inspection-testing.md).


## XML authoring alternative

`SettingsView.xml` is the checked XML equivalent of `SettingsView.pipe`. Add
`-DPIPEVIEW_VIEW_SYNTAX=xml` to select it explicitly; `pipelang` remains the default.
Both compile to the same document and typed action definition through the shared
checker. The receipt admits the selected source syntax and original input hash.
The build uses one source, without merging or automatic synchronization.
Use `pipelang-viewc --emit xml` or `--syntax xml --emit pipelang` for checked
semantic conversion. See the [XML contract](../../docs/concepts/pipeview-markup.md).

## Explicit native view parser and headless model checks

The Go view parser remains the default. Select the experimental native parser
only with both `PIPELANG_CPP_VIEW_PARSER` and its exact lowercase
`PIPELANG_CPP_VIEW_PARSER_SHA256`. The view compiler and adapter require the
selected parser identity in generated metadata; missing, mismatched or implicit
selection refuses without Go fallback. This parser slice supports PipeLang
view source only; XML plus native parser selection refuses explicitly.

`PIPEVIEW_SETTINGS_BUILD_NATIVE=OFF` builds the model, owned Save worker and
inspection fixtures using exact installed `ForgePipe::UI`, without requiring
`NativeHost`, Vulkan or Qt. The default remains ON and requires NativeHost for
the native showcase. Headless/model checks do not qualify visible presentation,
physical input or GPU behavior.


The fixed percent extension has local installed-SDK evidence for all four headless
compiler selections (Go, native parser, all native components, XML), strict v2
storage/legacy migration, owned worker capture and exact Go/native inspection.
The native entry point compiles against the qualified installed NativeHost SDK;
no percent-control UI session or physical input was run. The
[percent qualification record](../../docs/research/pipeview-percent-stepper.md)
separates these evidence levels.
